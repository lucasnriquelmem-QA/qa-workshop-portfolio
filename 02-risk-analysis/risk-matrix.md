# Risk Matrix
| ID | Riesgo | Impacto | Probabilidad | Nivel | Justificación |
|----|--------|---------|--------------|-------|---------------|
| R1 | [El sistema podría registrar el pago como aprobado pero no confirmar el pedido si la conexión se corta entre el checkout y la confirmación, dejando al cliente cobrado sin pedido registrado] | Alto | Media | Alto | [Impacta directamente dinero del cliente y confianza en la tienda; la probabilidad es media porque depende de un corte de red en una ventana de tiempo específica del flujo de checkout] |
| R2 | [Un usuario no registrado podría armar un carrito, y al loguearse en el checkout, perder los productos agregados previamente] | Medio | Alta | Alto | [Afecta conversión de ventas (abandono de compra); es un escenario común porque el flujo permite navegar sin login antes de comprar] |
| R3 | [El carrito podría mostrar una cantidad o subtotal desactualizado si el usuario modifica la cantidad de un producto y no se recalcula antes de avanzar al checkout] | Medio | Media | Medio | [Genera cobro incorrecto o reclamo del cliente; probabilidad media porque depende de una secuencia de acciones específica (editar cantidad justo antes de avanzar)] |
| R4 | [Un cliente registrado podría consultar el historial de pedidos y ver información de otro usuario si el control de sesión/autorización no valida correctamente el dueño del pedido] | Alto | Baja | Medio | [Expondría datos personales de otro cliente (impacto alto), pero requiere un fallo específico de autorización que suele estar cubierto por frameworks estándar (probabilidad baja)] |
| R5 | [El buscador/navegación de catálogo podría no devolver resultados o mostrar productos incorrectos al filtrar por una categoría con muchos ítems, afectando la capacidad del cliente de encontrar productos] | Bajo | Media | Bajo | [No compromete dinero ni datos, pero afecta la experiencia de búsqueda; probabilidad media al ser una funcionalidad de uso frecuente] |
| R6 | [El registro de una nueva cuenta podría aceptar datos de contacto inválidos (email mal formado, campos vacíos) si la validación de formato no es estricta, generando cuentas inutilizables (ej. sin poder recuperar contraseña)] | Medio | Media | Medio | [Afecta la calidad de datos del negocio y la capacidad del cliente de recuperar su cuenta; probabilidad media porque depende del nivel de validación implementado] |
